# Legacy canonical version election

`validateCanonical` and the twelve `Shared*` aliases elect shared-contract schema version `1.0.0`: UsageEvent, BudgetReservation, ReserveRequest, ReserveResult, SettleRequest, SettleResult, ReleaseRequest, ReleaseResult, QueryRequest, QueryResult, FinancialSummary and ErrorEnvelope. `LEGACY_CANONICAL_VERSIONS` records that immutable election. An SDK adding versions cannot widen these aliases or change a foreign version from `UNSUPPORTED_VERSION` to `VALIDATION_ERROR`.

The wrapper uses the installed SDK's existing `validateContract` and `canonicalJson` capabilities. Invalid JSON values and missing or nonstring versions retain the original validation error. A well-formed JSON object with a foreign string version receives the original unsupported-version envelope. Payloads are never relabeled or downgraded. Mapped legacy successes return a private recursively frozen canonical-JSON snapshot validated by the SDK, rather than preserving caller object identity or mutability. Ordinary payload fields remain structurally equal; SDK canonical JSON normalizes numeric negative zero to zero, while exact decimal strings are unchanged. Contract and payload bindings are captured once in original evaluation order. Source-version and snapshot-version disagreement is refused before SDK validation, and successful output contains only the same frozen data supplied to validation. This snapshot validates structural data and carries no grant or host authority. Other SDK contract names retain their existing dispatch and success identity. Error metadata is read only after the refusal decision is fixed; success never invokes metadata getters. Non-ContractError exceptions from the original JSON/version observation retain their identity. The public SDK remains pinned to proposal `0.3.0`; its absent `validateContractVersion` is not imported.

Finance's separate native version 2 reporting and budget boundaries remain independently elected. This legacy wrapper does not validate those payloads or replace economic, authorization, relationship or semantic checks. Offline checks with an authenticated private SDK are compatibility evidence, not SDK adoption or host authority.

Run `npm run build --silent && node --test tests/contracts/canonical-compatibility.test.mjs` for the 100 unchanged structural fixture payload/error cases with the explicitly elected snapshot-success oracle, twelve legacy elections, JSON/error precedence, mutable/getter/Proxy/reentry controls and public declaration checks. Original success-identity assertions from the earlier boundary are retained as historical evidence of this deliberate API change. Parse, relationship and semantic fixture modes are outside this structural wrapper test. Existing contracts and smoke suites remain separate checks.
