# Readonly Finance partition binding and private currentness

The reporting subpath exports `createFinanceLedgerPartitionBindingVerifier`, the closed local record schemas through `financeBindingRecordSchemas()`, and the explicit isolated owner-source adapter `createIsolatedFinanceSqliteCustodySource`. No root barrel, ledger store, migration, canonical contract, budget, Product route or operation permission changes accompany this module.

The default factory returns typed `unavailable`. Its only installed source adapter is explicitly `isolated_fixture`; it does not install a live issuer or grant and cannot claim supported production writer custody. Actual Product mapping admission remains unavailable until its owner establishes the reviewed source and writer closure. An empty query, zero expense, role label, valid signature alone or requested billing mode never supplies admission.

const { bindingVerifier, bindingCurrentness, guardLifecycle } =
  createFinanceLedgerPartitionBindingVerifier(configuration);
const observed = await bindingVerifier.verifyCurrentBinding({
  sourceTenantId, sourceProjectRef, scope, bindingReference, policyReference

`scope` contains tenant, project, actor, environment and billing mode. References contain actual owner `id`, positive integer `revision`, and `sha256:` hash. A verified observation contains detached frozen references, exact scope/source, actual selected backend reference, admitted lineage references, an epoch commitment, timestamps, and `provenance: "isolated_fixture"`. It remains an observation; it is neither `finance.summary.read`, `finance.summary.export` nor a provisioning permission. `denied` and `unavailable` use bounded exported reasons. Database errors do not expose raw source payloads or connection settings.

Binding and lineage signed envelopes are exactly `{unsigned, signature}`. Their unsigned bodies exclude self-hash and signature. Binding/source reference hashes cover canonical unsigned bytes; maintained head hashes cover the whole closed signed envelope. Each format has its own exact `format + "\n" + canonical(unsigned)` Ed25519 signing domain. SPKI hashes cover actual 44-byte Ed25519 DER bytes. Referenced policy/config/backend/custody artifacts retain their declared original UTF8 or canonical JSON byte semantics.

Canonicalization rejects duplicate keys before parsing, unknown signed fields, nonplain/proxy/accessor inputs, hidden/symbol properties, sparse/custom arrays, unsafe numbers, fractional numbers and noncanonical signature encoding. Source sequence is `0..2147483647`; signed-record and reference revisions are positive. Current independent registry/key/kind/action/scope/entitlement/principal/session, all five scope fields, source tenant/project, artifact refs, current head/body hashes, durable epochs and expiry must agree. A native signature under a wrong-kind/scope/entitlement key still refuses. Original expiry is clipped and never renewed by replay.

PG proof uses the independently selected host pool, a restricted ordinary role, a scoped repeatable-read readonly transaction, local timeouts, existing four-axis RLS binding, forced-RLS source tables, and exact core capability 11, including settlement migration 0011. Reporting 0012, reconciliation coverage 0013 and evidence reader 0014/0015 remain separate capabilities and do not increase this core count. It checks the exact current source head, current event and immutable root identity/hash. Actor admission remains independently signed/current because actor is not a PG partition column. It reads no money. A nonfinancial initial source at sequence0 can anchor a zero-expense partition, but the independent signed owner binding is still required. Wholly row-empty partitions are unavailable. Migration checksum bytes are not claimed from the ungranted migration table; capability 11 plus exact source-table/role/lineage checks are the supported current source model. A later core capability change requires coordinated review, not a broad future count.

The isolated native SQLite source reads already maintained records in the fixture's explicit custody layout. The adapter creates no tables. Its layout is a test/private composition contract, not a deployed Finance schema: state/epoch, signed-record snapshot and durable source-intent records. The owner fixture creates these tables and independent stored issuer/key/entitlement records. Its durable global epoch advances on authority/source updates, deletes, recreation and intent changes, covering both old and new subjects conservatively. Diagnostic reads do not change it.

The private `guardLifecycle` starts `BEGIN IMMEDIATE` on the original native connection before async preparation. Guards and handles live in original-factory private maps, bound to the exact frame, connection and invocation. `prepareCurrentness(guard, request, frame)` independently verifies the closed signed maintainer action and binding/source proof. It never promotes a returned observation or a caller Boolean. The frame is exactly `{format: "ci-finance-binding-mutation-frame-1.0.0", signedMaintainerActionCanonicalBytes}`.

A Product-owned coordinator must prepare its bounded mapping/receipt statements and all payloads before calling synchronous `validateCurrent`. It then executes the exact prepared writes and calls synchronous `commitGuard` on that original transaction with no intervening await or caller hook. `commitGuard` performs another actual coherent currentness check before native COMMIT. No SQL-bearing port or mapping mutation API is exported. Mapping/receipt writes exist only in the test owner coordinator; the Finance module controls the private transaction lifecycle. A final result escaped into a later microtask rolls back and cannot become a grant. Copied/foreign/ended/replayed handles refuse. Reentrant operations cannot reset the original busy fence. Provider loss rolls back held guards. An uncertain transaction end yields `indeterminate`; the owner must reconcile actual durable mapping/receipt state before claiming success or retrying.

Every supported PG source writer first commits a durable `changing` intent under the same owner SQLite exclusion. Only its original private broker then invokes the existing public ledger append API. It publishes active signed source/root/head records only after reading actual scoped PG evidence. A crash or uncertain publication leaves admission unavailable. A source writer beginning during the mapping check-to-commit interval cannot commit its intent, and therefore cannot start PG mutation, until the mapping transaction releases its SQLite guard. Direct runtime/ledger/administrative writer routes outside this broker are unsupported production custody. No polling cache, TTL lease or `channelHealthy` assertion substitutes for closure.
