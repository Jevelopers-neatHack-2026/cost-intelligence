# Finance source reconciliation, version 2 proposal

This source candidate is unreleased. Hosted PostgreSQL, crash/concurrency, full financial acceptance and consumer review are required. It does not promote the private development SDK or manufacture a host grant.

Root and `./reconciliation` export `startReconciliation` and `getReconciliation`. Version 1 caller-declared snapshot requests keep their previous unavailable behavior. Version 2 uses the same `RuntimePorts.budgets` PostgreSQL authority, current Finance permission and owner-controlled collector as settlement.

`BudgetReconciliationRequestSchema` requires `schemaVersion: '2.0.0'`, `requestId`, `idempotencyKey`, authenticated `scope`, `currency: 'USD'`, `jobReference`, `expectedCursorRevision`, `pageSize` (1–100), `ownerReference`, and `actionReference`. The full request is bound to replay. A changed owner, action, job or cursor under the same economic request key conflicts.

`BudgetReconciliationQuerySchema` requires version 2, `requestId`, authenticated `scope` and content-addressed `runId`. Its response is `BudgetReconciliationReceipt`: version, request/run IDs, `status` (`running`, `complete`, `needs_review`), replay flag, cursor revision/completed cycle, scanned/matched/unresolved counts, owner/action, timestamp, `unknownExposure`, `dispatchEligible: false`, and per-reservation action status/revision/error code. It contains no replacement balance or execution approval. All existing error codes remain unchanged.

The owner collector mounts `findAttemptEvidence({scope, attempt, authorityBinding})`, returning at most 16 `reportedCostRefs` and a nullable `finalityRef`. These are discovery hints, not authority. Every financial cost/finality is independently authenticated against original bytes, current issuer registry and the exact durable attempt/grant/model/target. No per-key aggregate is attributed to an attempt. Genuine finality is separate from reported cost. Production uses `finance_collector_v1`; the optional SDK decoder stays development-only.

A durable cursor plan precedes lookup and financial work. Each economic action has a deterministic command key and its own atomic ledger/hold transaction. A later immutable cursor entry journals the run outcome; it preserves the newest cursor watermark when another run progressed. Same-key completion replays its original receipt without performing new discovery. An interrupted run retries its durable plan and financial receipts. This does not claim an atomic multi-attempt run: already committed expense remains recorded if later work fails.

Released/final attempts remain in scans for late actual. Missing legacy source bindings remain unresolved. Unknown intake/capacity prevents a complete result. Missing or expired authority/source never means zero. Expiry retains positive unresolved holds; no-bill release requires current authenticated finality. Scoped quarantine blocks both original and replay reads under the shared ledger lock. Database wrappers refuse new statements/COMMIT after the run deadline, permit rollback, and retain ambiguous already-issued COMMIT outcomes. Actual process-kill and delayed-COMMIT proof remains required.

The caller response deadline races the entire orchestration, including pending database statements and cleanup. A timed-out call does not return a connection to the pool while its query or rollback is still in flight. Late non-cleanup statements are refused; an already submitted COMMIT remains an uncertain durable outcome and requires identical-key recovery. Pure injected-port controls cover pending BEGIN, scope binding and ROLLBACK. These controls do not establish PostgreSQL process-death or delayed-COMMIT acceptance, which remains a separate hosted requirement.

A saved candidate page does not freeze the collector's later discovery sequence or finality. If evidence changes after partial financial commits, the identical run can return an actionable `needs_review` receipt containing an idempotency conflict; already recognized expense and the remaining hold are preserved. The owner reads that receipt's current cursor revision, obtains current source references, and starts a new run with a new idempotency key and explicit action reference. This is distinct from replaying an identical completed run. The hosted regression withholds acknowledgement after actual server COMMIT, changes finality on retry, and checks this transition without issuing dispatch authority.
