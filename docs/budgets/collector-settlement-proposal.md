# Finance collector and settlement mapping

Implementation proposal under CI05B; independent full-candidate review and consumer acknowledgement remain required. The legacy shared-contracts 0.3.0 proposal pin and `adoption_accepted: false` remain unchanged. The bundled 0.10.1 alias is an explicit private DEVELOPMENT dependency, imported only by the reported-unsettled decoder. Settlement requires owner-mounted `reportedCostContractMode: development_0_10_1` and rejects production scope; this does not promote the proposal to canonical production adoption. Its structural helper does not authenticate an issuer, prove finality or authorize release.

`BudgetRuntimePorts.sourceCollector` is an owner-mounted `BudgetCollectorBackend`: `loadCurrent(reference)` returns a collector envelope and `loadCurrentIssuerKey(keyId)` returns independently configured current public key metadata. Incoming requests cannot supply registry entries. Keys contain `publicKeySpkiBase64`, `revoked`, `validFrom`, `validUntil`, and `allowedKinds`. Only public keys belong in runtime configuration. Signatures are Finance/host collector signatures, never purported provider signatures or Product purchase grants. Genuine backend/key issuance and consumer mounting remain downstream owner work; synthetic tests use generated ephemeral keys and a closed owner record store.

The envelope contains `record`, `recordSignature`, `current`, `currentSignature`, and original financial `sourceBytes`. The record version is `ci-budget-source-1.0.0` and binds `issuerKeyId`, `id`, `revision`, `predecessorHash`, complete financial `scope`, `provider`, `model`, `operation`, `targetBindingSha256`, exact attempt identities with nullable provider request ID, `kind`, original `authorityBinding`, truthful `evidenceMode`, `sourceFormat`, `sourceBytesSha256`, `observedAt`, and typed financial payload. The signed current head binds `recordId`, `revision`, `recordHash`, `scopeHash`, `verifiedAt`, `expiresAt`, and `revoked`. Source references use Finance contract `ci-budget-source`, schema reference version `1.0.0`, exact record ID/revision/content hash. These are Finance transport mappings, not new canonical contracts.

The resolver verifies signatures against the independent current registry, original byte hash, exact requested financial scope/target/attempt and current head. It reloads the head and issuer keys after asynchronous verification, retains the minimum consulted proof lifetime and fails closed on revocation, missing records or expiry. Distributed issuers do not thereby gain a universal atomic database fence. Mutation paths recheck current source and Finance permission around their transaction and acknowledgement boundaries; committed holds survive uncertain outcomes. Historical command replay is not fresh dispatch authority.

`ReservationRequest.pricingProfileRef` is required by the operational authority. `BudgetPricingProfileSchema` version `ci-budget-pricing-1.0.0` binds `pricingUnit` (`fixed_per_attempt`, `per_token`, `unknown`), exact currency, `economicRequestDigest`, nullable `fixedAttemptAmount`, and nullable `maximumPolicyRef`. Per-token or unknown pricing requires independently authenticated `BudgetMaximumPolicySchema` version `ci-budget-maximum-1.0.0`, with exact currency, original approved `policyRef`, `authorizedMaximum` and the same economic digest. The profile references the maximum collector record; its payload independently binds the approved policy reference carried by the request. Complete estimate labels do not convert per-token pricing into a fixed price: subtotal 0.01 with approved maximum 0.10 must request and hold the full 0.10. The operational engine refuses a 0.01 request against that maximum.

Pricing source formats are `finance_pricing_policy_v1` and `finance_maximum_policy_v1`; original JSON financial policy bytes must equal the typed policy payload. The economic digest includes every meaningful economic/provenance request field except outer `requestId` and the profile's own reference. That reference is authenticated separately by the exact signed profile; excluding it prevents a self-referential content hash. The original maximum-policy reference remains in the economic digest and is also bound by the maximum collector payload. Idempotency compares the entire normalized request, including both references.

Reported cost source format is `openrouter_images_response_v1` or explicitly synthetic `finance_synthetic_provider_response_v1`. Payload includes canonical UsageEvent 2.0.0, ProviderReportedCostEvidence 1.0.0, signed reference context, and explicit Finance amount semantics (`cumulative_attempt_total` or `distinct_charge`). Original `usage.cost` decimal tokens are read without binary floating conversion and compared to exact USD 0..18-decimal money. Missing cost, unsupported precision or conflicting original bytes are refused; known zero remains distinct from missing. The current cumulative settlement path requires cumulative semantics and cannot collapse multiple distinct expense heads into one alleged total. Aggregate evidence cannot manufacture attempt attribution. Provider-reported money has null RateCard and remains unpaid/unsettled; neither source cost nor the SDK sets reconciliation finality.

`BudgetExecutionFinalitySchema` version `ci-budget-finality-1.0.0` binds `state` (`partial`, `final_billed`, `final_no_bill`, `fenced_not_dispatched`), nullable `dispatchIntentRef`, nullable `cumulativeCostRef`, and nullable `fenceReference`. The collector key must be registered for execution finality. Format `finance_execution_finality_v1` binds original `financial_finality` bytes to that payload. Final billing must independently cover the exact cumulative cost; no-bill must bind durable intent and cannot erase known spend; never-dispatched release requires a current fence and durable absence of dispatch. A caller HTTP status or cancellation statement cannot issue this proof.

Settlement receipts preserve the exact original normalized command, returned outcome and proof commitments. Ledger-first scope locks precede currency budget locks, shared with intake/admission. Ledger expense replacement, source/posting provenance, financial finality, unused release and variance/exception records belong to one transaction. Uncertain transport/commit acknowledgement retains the hold and requires identical-key recovery. Financial expiry and revoked execution grants deny new work while attributable late actual expense is recognized under current Finance settlement permission. Migration 0011 preserves previous migration bytes and only extends three exact named valuation CHECK enums with `provider_reported_unsettled`; it adds immutable scoped provenance and queue records without a second balance system.

## Provider documentation checked on 2026-10-12

OpenRouter describes image pricing that varies by endpoint/model and reports cost when available. Its cancellation and disconnect notes distinguish multiple stages; those general statements do not authenticate a particular unresolved attempt. An image response without an identifier remains nullable. [Official image generation documentation](https://openrouter.ai/docs/guides/overview/multimodal/image-generation).

HTTP error classifications describe operational failures, not authenticated per-attempt billing finality. [Official errors documentation](https://openrouter.ai/docs/api/reference/errors-and-debugging), [official source with numeric codes](https://github.com/OpenRouterTeam/docs/blob/main/api_reference/errors-and-debugging.mdx).

Current-key usage fields are aggregate totals. Finance cannot attribute a delta to an invented generation or attempt by amount coincidence. [Official current-key documentation](https://openrouter.ai/docs/api/api-reference/api-keys/get-current-api-key). Generation lookup requires an existing generation identifier; it does not create an identifier for images. [Official generation lookup documentation](https://openrouter.ai/docs/api/api-reference/generations/get-generation).

These were documentation reads only. No provider billing/API request, private key or paid execution was used.
