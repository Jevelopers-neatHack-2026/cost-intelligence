# Finance collector production source proposal

Status: proposed Finance-owned extension, not released, not canonical adoption or a host mount receipt. The current staged decoder still supports only explicit `development_0_10_1` and refuses production. Implementation of the separate production decoder is continuing; this document does not claim it exists.

The proposed owner-mounted `reportedCostContractMode: 'finance_collector_v1'` will accept a signed `BudgetCollectorRecord` whose kind is `reported_cost` and whose financial payload has version `ci-budget-reported-cost-1.0.0`. It will independently validate current owner key purpose, revocation, expiry, source byte commitment, scope, original reservation host binding, provider/model/operation/target, and the exact billable attempt. Neither the caller nor the SDK helper supplies authentication. Genuine host grant issuance remains the existing independent host responsibility.

The proposed financial payload requires `version`, `observationId`, `economicUsageId`, `supersedesObservationId` (nullable), `evidenceId`, `evidenceRevision`, `predecessorEvidenceHash` (nullable), `amountSemantics: 'cumulative_attempt_total'`, `money: {amount, currency: 'USD', scale}` with exact nonnegative USD18, `observedAt`, and `usage: {completeness, units, missingFields}`. Usage units retain reviewed financial measure names, quantities, scales and inclusion relations. Scope, provider/model/operation/target and `attempt` remain required in the authenticated outer record; no caller mapping or aggregate-to-attempt attribution is permitted. The evidence digest is computed by Finance from the validated immutable financial payload. Missing/null source cost remains unknown and cannot produce this known-money record. Original source `usage.cost` must independently match the exact payload amount. Known zero is explicit.

Durable observation/evidence revisions require the exact current predecessor and reject forks, cycles and changed-body duplicate keys. Authenticated redelivery of the same observation does not create another expense. Execution finality stays a separate independently purpose-authorized signed `ci-budget-finality-1.0.0` payload; reported cost alone never releases a hold. Genuine late attributable expense remains recordable after execution grant expiry/revocation or prior release under current Finance settlement authority. No new dispatch authority follows from historical settlement replay.

Public functions remain `settle`, `release`, `recordExpenseAdjustment`, `markDispatched`, `getReservationSnapshot`, `revalidateAuthorization`, `retainUnknownOutcome`, `expireAuthorization`, `recoverReservations`, and exception/reconciliation operations from the budgets/reconciliation modules. Production cost settlement/read/release use explicit Finance request/receipt schema `2.0.0` with exact USD18; legacy `1.0.0` precision and canonical envelopes stay unchanged. The Finance reservation ID and attempt tuple must come from the authorization receipt/original request; external reservation/grant/attempt references cannot be invented or matched by amount.

The private alias `@jevelopers/shared-contracts-reported-development` remains reviewed 0.10.1, development opt-in only. The proposed production decoder will not call its caller-context validation helper as authentication, replace the legacy 0.3.0 pin, set adoption accepted, or label a Finance payload as a canonical UsageEvent. Finance owns the local transport contract; upstream canonical and consumer review receipts remain separate.

# Runtime-readable provenance

The independently mounted owner collector retains original authenticated response bytes and signed originals. Ordinary financial tables retain only original hash/reference/signature verification evidence and the versioned `ci-budget-financial-provenance-1.0.0` projection. Redacted financial facts are not labelled original bytes and are not claimed to reproduce the original byte hash. Arbitrary provider/collector payload extras never enter source rows or command proof receipts. The in-memory resolver bounds original source bytes to 1 MiB before parsing/verification. The current projection keeps only cost facts, observation/evidence commitments, or typed financial pricing/finality facts. Privacy quarantine under the existing scoped ledger lock makes capacity and financial actions unavailable instead of reading restricted expense as zero.
